# Nanexus V0.1 — Architecture Overview

Public overview of the V0.1 Investigation Agent. For product intent and examples, see the project README. For operator Web Console detail, see [web-console.md](web-console.md).

## Placement

Nanexus is an **independent investigation agent** that runs **alongside** an existing VMS/NVR. V0.1 integrates with Frigate over authenticated, **read-only** APIs. The VMS retains recording, detection, and primary storage. Nanexus owns planning, guarded tool execution, evidence handling, reporting, and durable Case storage.

## Control flow

1. The single-page Web Console admits a Case (question, authorized cameras, time bounds).
2. A thin FastAPI worker runs **one** LangGraph investigation controller.
3. A local chat model proposes the next authorized tool; a **Tool Registry** and **Tool Guard** enforce scope, budgets, and anti-repeat.
4. Tools may:
   - search VMS detection/event metadata (`search_events`);
   - compute deterministic temporal relations locally (`analyze_temporal_relations`);
   - optionally retrieve a snapshot (`resolve_media`) and run a local VLM (`observe_media`) **only when** the planner selects those media tools, media retrieval succeeds, and local vision capability is enabled/available.
5. Observations, evidence, receipts, and relations are registered as Case artifacts.
6. Claims are drafted and checked; an **Output Gate** accepts only an evidence-grounded report when finalization succeeds (runs may also end `partial` or `failed` with disclosed limitations).
7. Case/Claim/Report (and cited relations) persist in local SQLite; retained snapshots are Case-bound and integrity-checked.
8. Operators can reopen a Case from durable artifacts without re-querying the VMS or models.

Visual retrieval and VLM interpretation are **selective and optional**. Ordinary event or temporal investigations often never download media or invoke the vision model.

## Evidence layers

Keep these distinct when reading a report:

| Layer | Meaning |
|-------|---------|
| VMS event metadata | Detections returned by the authorized API |
| Computed temporal relations | Deterministic proximity/ordering over registered observation intervals |
| Local model interpretations | Qualified VLM text over retained snapshot bytes |
| Integrity checks | Case-bound media with content-hash verification when served |

NEAR means **temporal** proximity only — not physical interaction, shared identity, ownership, or causation.

## Design rationale (summary)

- **Bounded planning + Tool Guard** — the model proposes; it cannot invent tools, widen cameras, or bypass budgets.
- **Deterministic temporal engine** — gap/NEAR math stays separate from free-form model prose and from VMS retrieval.
- **Selective visual path** — snapshots and VLM cost are opt-in.
- **Evidence-backed Claims** — report statements must cite artifacts the Output Gate can check.
- **Durable Cases** — audit and reopen without re-hitting the VMS or models.

## V0.1 scope

Verified Frigate-first side-by-side investigation with local models. Not a VMS/NVR replacement, not multi-user cloud auth, not person identification or cross-camera Re-ID, and not exhaustive clip-wide video understanding.
